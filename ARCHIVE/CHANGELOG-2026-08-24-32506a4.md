**Prerequisite: Session Guidelines**

Ground rules set before any section work began, and held for the entire refactor:

- Tab Candy is a new plugin, full stop — new Obsidian id, no "legacy" anything carried forward.
- Comments describe current behavior only; no "old"/"used to"/"legacy" historical markers in code.
- No `@ts-ignore`, anywhere.
- `main.ts` is lifecycle-only — everything else lives in `src/services` or wherever else is appropriate.
- `updates.ts` (comparison material) is excluded from all rename/cleanup/lint/deletion/validation work.

**§0 — Decisions And Baseline**

Every item in this section was resolved; full rationale lived in `REFACTOR-DECISIONS.md`, current-state capture in `REFACTOR-BASELINE.md` (both now folded into this archive):

- **Plugin id**: `tabcandy` — a new, unrelated community-plugin identity. Anyone on the old `beautitab` id is treated as a fresh install, not an upgrade; accepted as a deliberate one-time cost.
- **Minimum Obsidian version**: `0.15.0` at this point in the project (later revised upward — see §5's and the tests-and-CI session's changelogs for the final `1.13.0`). The binding API at the time was `requestUrl` (0.13.25); `0.15.0` already cleared it. (This entry was later found to have been wrong about `revealLeaf`'s actual floor — corrected in §5.)
- **Node range**: `>=24` for development and CI, confirmed.
- **Bookmarks**: kept as a feature, isolated behind a guarded adapter (`services/bookmarks.ts`) that returns an empty list instead of throwing when Bookmarks is disabled, missing, or malformed — since `internalPlugins.plugins.bookmarks` is a private API with no public replacement yet.
- **Folder scanning**: non-recursive, matching existing behavior and the existing settings copy ("not including subfolders").
- **View activation**: replace the old "hijack every empty leaf on every `layout-change`" behavior with an explicit "Open Tab Candy" command plus a reusable `activateView()` helper (reuse an existing leaf via `getLeavesOfType()`, else create one, then `revealLeaf()`). The old auto-replace convenience is kept, but as an opt-in setting (default on) layered on the same helper, not an uncontrolled separate path.
- **Disposable dev vault**: convention documented (a vault path outside the repo, e.g. `~/.obsidian-dev-vaults/tab-candy/`, wired through an env var replacing the hard-coded Windows dev-output path removed in §1). Actually creating the vault is a local, out-of-sandbox step.
- **Baseline capture**: done — full current-behavior snapshot of settings/defaults, all background sources, both search buttons, bookmarks, quotes, recent files, view opening/hijacking, and reload/startup behavior, used as the regression reference for every later section.
- **Working tree**: verified clean; `updates.ts` didn't exist yet on this branch, so the exclusion rule had nothing to bite on yet, but stands for whenever it lands.
