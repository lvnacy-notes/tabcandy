**§4 — Vault-Based Backgrounds And Mobile Support**

- **`fs`/`path`/electron removal made permanent.** §1 dropped these as a stopgap; this section builds the real vault-relative replacement, so it's genuinely true now rather than true-until-the-rebuild-arrives.
- **`getResourcePath()` instead of `readBinary()` + object URLs.** REFACTOR.md's original sketch was to read image bytes and manage an object-URL lifecycle (create/revoke). Built differently: `app.vault.adapter.getResourcePath(path)` turns a vault-relative path directly into a URL usable in `<img src>`/CSS `background-image` — no bytes read, no `Blob`, nothing to revoke. Meets every actual goal (no image bytes in settings, mobile-safe, no leak) with less code and no cleanup surface to get wrong.
- **Two background fields, not one.** `backgroundFiles` (folder-sync, machine-managed, replaced wholesale on every sync) and `manualBackgroundFiles` (individually-added via the vault image picker, user-managed, appended/removed one at a time) are kept separate — folding manual picks into the sync-managed array would have silently deleted them on the next "Sync now" or plugin reload.
- **Manual image picker rebuilt to match.** `ChooseImageSuggestModal` already resolves a `TFile` inside the vault, so it now stores `file.path` directly instead of reading bytes into a base64 `data:` URI. Also now shares one extension list with folder sync, fixing a real pre-existing drift (folder sync allowed all five supported formats, the manual picker only two).
- **Vault-folder chooser replaces the OS picker.** `ChooseBackgroundFolderModal` is a `FuzzySuggestModal<TFolder>`. Deliberately doesn't use `Vault.getAllFolders()` — it needs Obsidian 1.6.6, past this project's locked floor at the time — and instead hand-walks `TFolder.children` recursively, which is older than the project's minimum and doesn't depend on a method that postdates it. The text field is kept alongside the new "Browse" button, not replaced.
- **Cache invalidation via real vault events.** `create`/`modify`/`delete`/`rename` listeners in `main.ts` (auto-cleaned up via `registerEvent()`) trigger a debounced re-sync for the configured folder and directly update/drop affected `manualBackgroundFiles` entries wherever they live in the vault. `pruneMissingManualBackgroundFiles()` runs once on load to catch anything that changed while the plugin wasn't running. `Settings.ts` also filters both lists defensively before rendering as a last line of defense. **Known, accepted gap**: a stale entry can render for up to ~500ms between a file change and the debounced re-sync landing — a race, not a crash, not worth a more complex synchronous story.
- **Mobile support was the point of the rebuild.** No `isMobile` gate anywhere in the new sync code or settings UI. **Not actually verified on-device, though** — `typecheck`/`lint`/`build` all pass and the new code was reasoned through against the `obsidian` type declarations, but real desktop/mobile testing with a synced vault, and testing the add/modify/rename/delete/sync event paths specifically, weren't possible from this sandbox and remain open.
- **Process finding, recorded plainly**: an earlier pass at §3's legacy-field question was implemented exactly as first decided (a dismissible notice, indefinite base64 rendering), then reversed on review for conflicting with Session Guideline #1. Stale "pre-refactor"/"no longer written" comments from that same pass (a Guideline #2 violation) were also found and rewritten in `ChooseImageSuggestModal.ts` and `Types/Images.ts`, in files that predated this section entirely. Lesson stated for later sections: check a planned decision against the Session Guidelines *before* implementing it, not only as an after-the-fact review.
- **Incidental main.ts cleanup, pulled forward.** Touching `main.ts` for the new vault listeners was also used to finish enforcing the "lifecycle-only" Session Guideline on it: command execution (`src/services/commands.ts`), the explicit-activation/opt-in-hijack behavior §0 already locked in (`src/services/newTabHijack.ts`), and the plugin-update check (`src/services/versionCheck.ts`) were all extracted out into `src/services/`. The full command/bookmark-typing and activation-vs-hijacking write-ups still belong to §5/§6 and will get their own complete treatment there — this is the code landing early, not the decision being made early.
- **Lint delta double-checked, not just totals.** Re-measured after the §3 correction above: 139 errors/31 warnings, diffed message-by-message (not just by count) against the true pre-session baseline. The one net-new warning is a sentence-case flag on changed setting-description text, not a new class of finding.
