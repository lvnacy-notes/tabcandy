**§3 — Settings Schema And Persistence** 

- **Schema versioning**: `settingsVersion: number` added to `TabCandySettings`, stamped onto every settings object on load (including a fresh install with no `data.json`) via `CURRENT_SETTINGS_VERSION` in `normalizeSettings.ts`.
- **Validation at the load boundary**: `normalizeSettings()` is a pure function (no Obsidian API, no side effects) that merges defaults and validates loaded data — enum fields (`backgroundTheme`, `timeFormat`, `bookmarkSource`, `quoteSource`) via the shared `isEnumValue()`, search providers via `isValidSearchProvider()` (falls back to the built-in provider wholesale rather than patching a half-broken object). Wired into `main.ts`'s `loadSettings()` in place of the old unchecked `Object.assign()`.
- **Legacy fields: decided, then corrected mid-implementation.** There's no Beautitab-origin data to handle at all — `tabcandy` is a different plugin id, so it's a fresh install, not an upgrade. That left `localBackgroundsDirectory`, `legacyBackgroundsNoticeDismissed`, and base64 `localBackgrounds` as the real question. An earlier pass kept these in place behind a dismissible one-time notice, reasoning that closing the write path was enough. That conflicted directly with this project's own Session Guideline ("anything 'legacy' must go") and was corrected before landing: **all three fields, the notice, and the base64 render/delete block are deleted outright.** Anyone upgrading with a configured OS folder or saved base64 images loses that configuration from the settings UI entirely — nothing in the running plugin reads, writes, or displays any of it anymore. REFACTOR.md's own Migration section (which describes exactly the notice-and-marker approach that got reverted) is treated as superseded by the Session Guidelines wherever the two conflict.
- **Settings store**: `src/Settings/SettingsStore.ts` replaces the old untyped `Observable` everywhere (`main.ts`, `ReactView.tsx`, `App.tsx`). `TabCandyPlugin.settings` stays a plain field — `tsc` rejects overriding it with a getter (`TS2611`) since Obsidian's own `Plugin` class declares it as a plain property — kept in sync instead via a `settingsStore.subscribe()` call in `onload()`. All ~17 write sites in `Settings.ts` now go through a single `updateSettings()` helper instead of each repeating a mutate/notify/save/redraw block by hand; array-valued settings switched to whole-array replacement instead of in-place `push`/`splice`.
- **Confirmed real bug**: `Observable`'s unsubscribe filtered subscribers with `value === callback` — keeping the match instead of removing it, the exact opposite of a working unsubscribe. `SettingsStore` uses a `Set`/`.delete()`, which has no equivalent way to get backwards. `Observable.ts` itself is left in place as now-fully-dead code; its removal is explicitly §8's job.
- **Debounced text fields**: the three free-text settings (`customBackground`, `greetingText`, `backgroundsFolder`) now debounce their writes 500ms via the new `debounce()` utility, bound once in the `TabCandySettingTab` constructor rather than inside `display()` — binding it inside `display()` would lose the pending timer on every redraw (which happens on nearly every other setting change), silently dropping mid-keystroke input.
- **Deferred to §10**: testing fresh defaults, partial settings, and malformed settings against `normalizeSettings()` — blocked on a test runner not existing yet, same as §1's open test-script item. Written as a pure function specifically so it's ready to go the moment §10 lands one.
