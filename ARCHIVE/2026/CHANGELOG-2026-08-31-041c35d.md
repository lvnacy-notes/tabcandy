## Notes

**Commit Message**
chore: refactor, part 9, type system hardening and full cleanup

**Lint/type fixes**:
- `main.ts` — narrowed `loadData()`'s any to `unknown` at the boundary
- `esbuild.config.js`/`package.json` — replaced the third-party `builtin-modules` dep with Node's own `node:module`
- `TabCandyView.tsx` — dropped pointless async on `onOpen()`/``onClose()`, return `Promise.resolve()` to satisfy `ItemView`'s actual contract
- `getBackground.ts` — added a validated `toMonth()` boundary instead of comparing a raw number against enum members; converted `SEASONAL_THEME` from an enum to a `const` object + literal-union type (three holidays intentionally share the 'fireworks' tag — enums can't do that, plain objects can); fixed the missing block scope in the switch
- `ChooseBackgroundFolderModal.ts` — deleted the whole file once the native folder control replaced it
- `SettingsTab.ts` — centralized `settings-save` error handling in one place, `void`-marked ~19 intentionally-fire-and-forget writes, fixed real sentence-case violations (URL, JPG/PNG/GIF as acronyms, a stale quoted command name that didn't match what's actually registered)
- "Tab Candy" proper noun — registered as a brands option on `obsidianmd/ui/sentence-case` rather than disable comments, since `eslint-plugin-obsidianmd`'s own recommended config hard-blocks disabling any `obsidianmd/*` rule inline

**The SettingsTab.ts migration**:
- `minAppVersion` bumped to 1.13.0, `display()` deleted entirely, rebuilt on `getSettingDefinitions()`/`getControlValue()`/`setControlValue()` — the latter two routed through `settingsStore` rather than the default (which would've bypassed subscriber notifications the live view depends on)
- Not originally a planned §9 item — surfaced by lint's deprecation warning on `display()` itself. `minAppVersion` was already `1.7.2`, and with nothing shipped to any users yet, there was no upgrade-compatibility cost to paying the small remaining gap up to `1.13.0`, so the migration was done in full rather than left half-supported.
- The manual `background-image` gallery is now a native `SettingDefinitionList` with built-in `add`/`delete`/`keyboard-delete`, replacing hand-rolled DOM + a `ConfirmModal` confirmation step (dropped intentionally — deleting a reference is low-stakes and instantly re-addable)
- `backgroundsFolder` uses the native folder control (vault suggester built in), which fully replaced `ChooseBackgroundFolderModal` — that file and its whole `FuzzySuggestModal` subclass are gone
- Picking a folder via the native suggester no longer auto-triggers a re-sync the way the old "Browse" button did — "Sync now" sits right next to it as an explicit action
- `ChooseImageSuggestModal`, `ChooseSearchProvider`, `CustomQuotesModal`, and `ConfirmModal` remain as custom modals — their settings are array/object-valued or otherwise don't map onto any single native control type.

**Incidental fix**: this section's `typecheck` pass turned up two leftover errors that weren't type-system gaps at all — `src/Settings`/`src/Utils` had never actually been renamed to lowercase on disk despite every import (and the §8 decisions log) assuming they had, plus an orphaned duplicate `src/modals/ChooseSearchProvider.ts`. Both cleaned up as part of getting `typecheck` back to zero errors before moving on.
