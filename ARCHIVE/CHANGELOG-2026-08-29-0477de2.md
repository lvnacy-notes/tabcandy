## Notes

**Commit Message**
chore: refactor, part 5, public obsidian api and lifecycle

**§5 — Public Obsidian API And Lifecycle**

- **`FileView` → `ItemView`.** Tab Candy isn't file-backed, so `allowNoFile = true` and an unused `file` field were working around a base class that doesn't fit. The constructor also stopped taking an explicit `app` parameter — `View`'s own constructor already populates `this.app` from the `leaf` it's given. `contentEl.empty()` now runs at the top of `onOpen()` defensively, and `onClose()` nulls `this.root` after unmounting.
- **Explicit activation vs. hijacking, implemented per §0's earlier decision.** `src/services/newTabHijack.ts` now holds three pieces: `setLeafToTabCandy()` (the one place that calls `setViewState()`), `activateView()` (the new "Open new tab" command's implementation — reuse an existing leaf via `getLeavesOfType()`, else create one), and `registerNewTabHijack()` (the opt-in, default-on watcher). **Deliberate scope call**: the hijack watcher does *not* route through `activateView()`'s reuse-check — it keeps today's exact `getMostRecentLeaf()` + empty-view-type behavior, since making it fully reuse-aware would leave a newly-opened empty tab empty whenever a Tab Candy tab is already open elsewhere, defeating the setting's point. New setting: `replaceEmptyTabsWithTabCandy` (boolean, default on). New command: `open-tab-candy` / "Open new tab," named to avoid redundantly repeating the plugin name (Obsidian already prefixes commands with it).
- **`minAppVersion` bumped `0.15.0` → `1.7.2`.** `activateView()` needs `workspace.getLeaf()` (0.16.0) and `workspace.revealLeaf()` (1.7.2); `getMostRecentLeaf()` needs 0.15.4. No version-safe, non-deprecated alternative exists for any of these. Bumped to the highest floor actually in use, no higher — resolves all four `no-unsupported-api` findings from this section at once rather than working around them individually. This also corrects an error in §0's original analysis, which had incorrectly listed `revealLeaf` as pre-1.0 (left in place with a correction note, not silently rewritten). Also found and fixed while touching version files: `versions.json` still carried Beautitab's entire release history mapped to the old floor — reset to a single current entry.
- **Lifecycle audits, mostly clean.** `registerEvent()` verified used everywhere an Obsidian event is registered. `registerDomEvent()`: audited, no change needed in this section's files — the one raw `addEventListener()` in a lifecycle file is dev-only tooling outside any Plugin/Component instance, dead-code-eliminated from production builds; the others sit in Modal/Settings render functions that already tear listeners down via `.empty()` on redraw. `registerInterval()`: the only interval in the codebase is React's own clock tick in `App.tsx`, already cleaned up via `useEffect` — can't be moved to `Component.registerInterval()` without threading the view instance through React context, which is §7's job, not this section's. Empty `onunload()` removed from `main.ts`.
- **No literal singleton existed.** The "global view-instance assumptions" item turned out to be architectural, not a held module-level reference — `getMostRecentLeaf()`-driven blanket hijacking was standing in for "the" new-tab slot on every `layout-change` event. Fully addressed by the activation rework above.
- **Mobile-emulation dev code removed outright.** The `app.emulateMobile()`/`app.isMobile` block in `main.ts` and its four `@ts-ignore` comments are deleted per REFACTOR.md's explicit instruction, confirmed absent from `dist/main.js`.
- **Private/internal API audit, classified not yet fixed.** A full sweep (`eslint-plugin-obsidianmd`'s rules plus a manual grep) found: the mobile-emulation block (resolved above); `getLeaf()`/`revealLeaf()` vs. the old floor (resolved by the `minAppVersion` bump); and three pre-existing files — `src/services/commands.ts`, `src/modals/ChooseSearchProvider.ts`, `React/Utils/getBookmarks.ts` — explicitly left for §6, which already owns isolating/guarding exactly this private-registry access.
