**§8 — Consolidate The File Structure**

- **New layout**: `src/app/`, `src/services/`, `src/settings/`, `src/ui/modals/`, `src/utils/`, and one flat `src/types.ts`. `main.ts` stays at the repo root — Obsidian/esbuild entry-point convention, not an oversight.
- **`types.ts` went further than the checklist asked.** The item only named merging `Enums.ts` + `Interfaces.ts`; Lvnacy asked for every type in the codebase to have one point of origin, so `TabCandySettings` and `Quote` (previously declared inline in `Settings.ts` and `getQuote.ts`) moved in too. Kept as one flat file rather than a `types/` directory — the combined surface is only ~100 lines. One dead type (`Image`, zero consumers) was found and cut during the consolidation.
- **Naming rule corrected mid-pass.** The original rule ("camelCase unless it exports a class") was applied literally at first, which would have renamed `App.tsx` to `app.tsx` despite `App` being a function component. Corrected once flagged: components get PascalCase filenames matching normal React convention, classes get PascalCase regardless of component status (`ReactView.tsx` → `TabCandyView.tsx`, matching the class it exports), and everything else (hooks, services, utilities, non-class settings modules) stays camelCase. `main.ts` is a deliberate, permanent exception for the entry-point reason above.
- **`Settings.ts` split in two**, since a class file can't also hold non-class exports once the one-class-per-file rule is actually enforced: `src/settings/SettingsTab.ts` (the `TabCandySettingTab` class) and `src/settings/defaultSettings.ts` (`DEFAULT_SETTINGS`/`DEFAULT_SEARCH_PROVIDER`/`SEARCH_PROVIDER`). Pure code motion, no behavior change.
- **Import strategy decided: relative imports everywhere, no alias.** Auditing for this section surfaced a real split — some files used bare specifiers that only resolved through `tsconfig.json`'s blunt wildcard `paths` entry (itself a forced side effect of `tsgo` rejecting `baseUrl` back in §1, not a chosen alias strategy), others used genuine (sometimes quite deep) relative imports. Flagged before any files moved, since moving first would've meant re-deriving both styles' new paths. Decision: relative imports everywhere. The now-purposeless wildcard `paths` entry wasn't removed from `tsconfig.json` in this pass — flagged for §9 instead.
- **`manifest-beta.json` deleted outright.** Investigated before wiring it up as originally asked: modern BRAT (v1.1.0+) reads `manifest.json` straight from GitHub release assets and never touches a root-level `manifest-beta.json` at all — it's documented as retained for backwards compatibility only. The real modern mechanism (a release workflow publishing tagged releases with the plugin's files as assets) is tracked as new CI scope instead of bolted onto this section.
- **Checklist renumbered.** A new §9 (Type System Hardening And Full Cleanup) was inserted at Lvnacy's explicit request — a dedicated pass to eliminate every remaining `any`/`unknown`, review every `as` assertion, and clear every remaining lint/typecheck finding (including several categories left for triage-only earlier) before testing/CI work begins. Old §9 (Tests And CI) → §10, old §10 (Release And Documentation) → §11, old §11 (Final Audit And Sign-Off) → §12. All cross-references elsewhere in the checklist were updated to match.
- **`Function`-typed callbacks fully closed out.** `ConfirmModal.ts`'s `_onConfirm: Function` and `CustomQuotesModel.ts`'s `_onSave: Function` (both left open since §1) are now properly typed. While already in `CustomQuotesModel.ts` for that fix, two more `any`-typed change-event handlers and one implicit-`any` `JSON.parse()` result were found and fixed alongside — same class of issue, not worth leaving for §9 given the file was already open.

**Heads up for the next couple of commits**: the case-only directory renames in this pass (`Settings/`→`settings/`, `Utils/`→`utils/`, etc.) didn't land cleanly — the two changelogs immediately following this one (`e3c8e3e`, "repair damage from old failed git patch," and `6ab7ffb`, "correct case-only directory rename") exist specifically to clean that up.
