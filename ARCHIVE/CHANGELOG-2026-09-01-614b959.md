**§10 — Tests And CI (Prep)**

This commit is pure preparation — no test files, `vitest.config.ts`, or CI workflow exist yet. It establishes the rules the actual test-writing (next commit) and CI wiring (final commit) will be held to:

- **Testing Specification drafted**: philosophy (a short, explicitly-named list of "load-bearing" behaviors held to a much higher bar than everything else — settings normalization, the settings store's subscribe/unsubscribe correctness, background resolution against a real vault's mess, view lifecycle not leaking React roots, and the two private-API files failing closed rather than open) plus a trust-boundary rule (test this codebase's usage of Obsidian/React/the vault adapter, never those dependencies' own internals).
- **Vitest chosen as the test runner**, closing the item left open back in §1. ESM-native (matches the project's `"type": "module"` setup with no shims), one dependency instead of assembling a runner + assertions + mocking + coverage by hand, and pairs natively with `obsidian-test-mocks`'s own Vitest setup file.
- **Vite-library-mode-replaces-esbuild was also proposed here** — untested at the time of writing, reasoned from the architecture (one shared transform/bundler stack for both tests and the production build). This is the one piece of this document that didn't survive contact with reality: attempted in the very next work session and reverted after Vite's `build.lib` API couldn't handle Obsidian's two-independent-output-file shape (`main.js` and a CSS-only `styles.css` nothing in JS imports) without either crashing outright or silently tree-shaking the plugin class itself out of the bundle. `esbuild.config.js` was kept; Vitest was kept regardless, per the spec's own fallback clause.
- **Docs reorganized** while writing new ones: all `REFACTOR docs/*.md` moved under `docs/` alongside the new testing documents, so project documentation lives in one place rather than two.
- **A real, if minor, regression was introduced and left uncaught in this same commit**: dropping `esbuild-copy-static-files`/`esbuild-sass-plugin` from `package.json`'s `dependencies` while `esbuild.config.js` still imports both directly. `pnpm run build` would fail from a fresh install at this exact commit. Caught and fixed in the very next session — flagged here for the record since it briefly broke the build during doc-writing, the lowest-risk kind of commit to have that happen in.
